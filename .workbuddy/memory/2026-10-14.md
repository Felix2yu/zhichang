## 生产 500 排障：nil slice 编码成 JSON null（重要约定）
- 现象：部署生产后概览/睡眠等页 500 Internal Error，报 `null is not an object (evaluating 'y(j).at')`
  与 `Spread syntax requires ...iterable not be null or undefined`；**容器无任何报错**。
- 根因链：query.go 里 `var out []SleepRow` 等 6 处 nil slice → 空结果集被 encoding/json 编成 `null`
  → 前端 `sleep = sl.rows` 得到 null → `sleep.at(-1)` / `[...rows].reverse()` 抛 TypeError
  → SvelteKit 客户端错误边界接管，渲染默认错误页（即用户看到的 500）。ssr=false 所以并非服务端 500。
- 为什么本地不复现：本地库有数据，走不到空结果分支；生产空库/区间无数据才暴露。
- 修复（双层）：
  1. 后端 query.go 全部改为 `out := make([]Xxx, 0, N)`；`DailySeries` 空指标返回 `[]DailyPoint{}` 而非 nil；
     `SyncStatusOf` 显式初始化 RecentRuns/Watermarks/MissingDays 三个 slice。
  2. 前端 web/src/lib/api.ts 加 `arr<T>()` 兜底，所有 api.* 返回前把可能为 null 的数组字段过一遍
     （含 daily 的 series 每个 value），页面侧零改动。
- 新增 internal/store/postgres/json_contract_test.go：锁定「空结果集必须编成 []」，
  含 nil slice 编成 null 的对照组，以及直接驱动 collectDaily 空路径的用例（不依赖数据库）。
- **项目约定（后续新增查询必须遵守）**：任何返回 slice 的 store 方法都要用 make 初始化，
  绝不 `var out []T`；JSON 响应里的数组字段不允许出现 null。

**踩到的坑（都是实测截图发现的，编译期一律看不出来）**：

### 判定归一化是本次最核心的一步（internal/domain/ecg/classify.go）

`classification` 是**本地化显示串**，直接当枚举存会在换手机语言时把历史数据劈成两半。
新增唯一事实来源 `ecg.Classify(raw) Code`，9 个稳定 code：
`sinus_rhythm` / `atrial_fibrillation` / `high_heart_rate` / `inconclusive_low_heart_rate` /

`unrecognized` / `unknown`。库内**两列都留**：`classification`（原文）+ `classification_code`（规范）。
`DisplayZH(code)` 给中文展示名；`CodeUnknown` **刻意不给展示名**——认不出就照原样展示并标注
「上游原文」，别让人误以为是我们的措辞（前端已按此实现）。

**判定顺序是关键，写错过一次（测试逮住）**：
1. `poorRecording`（记录欠佳）最先；
2. `lowOrHigh`（低心率或高心率 / 高低心率）→ 只能给笼统 inconclusive；
3. `afib && afibNegated` → ECG v2 的「高心率-侦测不到心房颤动」既含「心房颤动」又含「高心率」，
   实为**高心率且无房颤**，须靠 `侦测不到/未检测到/not detected` 否定词抢先分流；
4. 含 inconclusive/unrecognized 标记 → 再细分 low/high/unrecognized/笼统；
5. 最后才 afib → sinus → highHR。
`normalize()` 先拍平 NBSP(`\u00a0`)、表意空格(`\u3000`)、各种连字符与引号变体、转小写、折叠空白，
并覆盖简繁两套关键词（`記錄欠佳` / `無法辨識`）。

### 重量版（波形）

- `ecg_voltages` 表（`ecg_id` 主键 → `ecg_records.id`，`ON DELETE CASCADE`），
  `voltages double precision[] NOT NULL`。**两表分家**：15360 点 ≈ 120KB，比元数据大 5 个数量级，
  同表存储会让列表查询每次都把波形拖出来（TOAST 不隔离读取）。
  用 `double precision[]` 而非 `bytea`：pgx 原生扫 float64 数组、psql 里可读、9 条共约 1MB，
  不值得为它写自定义 codec。
- **任一点缺 voltage 就整条波形丢弃、只留记录**——横轴是索引推导的，缺一个点后面全部错位。
- 记录用 `ON CONFLICT DO NOTHING ... RETURNING id`，`pgx.ErrNoRows` 时回查一次，
  这样后到的波形能补挂到已存在的记录上（`WriteECG` 的回填路径）。
- `/api/ecg/waveform?id=`：记录不存在 → 404；记录在但无波形 → 200 + `[]`（两者语义不同，不能混）。
- 单位**原样保留 `mcV`**，不换算（HAE 文档举例写 `"V"`，实测给 `mcV`；按项目约定
  `ConvertUnit` 只登记数值等价换算，未知单位宁可原样留）。

### 环境小记

- `pkill -f tmp_dev` 之后 embedded-postgres 的 `postgres` 子进程会留下占住端口，
  要再按端口找到 PID 单独 kill，否则下次起库报端口被占。
- 迁移里用 `CREATE TEMP TABLE ... ON COMMIT DROP` 收集受影响集合是安全的：
  迁移是「按序、单事务、可重入」（见 `migrate_test.go` 的口径）。
