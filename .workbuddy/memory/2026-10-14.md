## 生产 500 排障：nil slice 编码成 JSON null（重要约定）
- 现象：部署生产后概览/睡眠等页 500 Internal Error，报 `null is not an object (evaluating 'y(j).at')`
  与 `Spread syntax requires ...iterable not be null or undefined`；**容器无任何报错**。
- 根因链：query.go 里 `var out []SleepRow` 等 6 处 nil slice → 空结果集被 encoding/json 编成 `null`
  → 前端 `sleep = sl.rows` 得到 null → `sleep.at(-1)` / `[...rows].reverse()` 抛 TypeError
  → SvelteKit 客户端错误边界接管，渲染默认错误页（即用户看到的 500）。ssr=false 所以并非服务端 500。
- 为什么本地不复现：本地库有数据，走不到空结果分支；生产空库/区间无数据才暴露。
- 修复（双层）：
  1. 后端 query.go 全部改为 `out := make([]Xxx, 0, N)`；`DailySeries` 空指标返回 `[]DailyPoint{}` 而非 nil；
     `SyncStatusOf` 显式初始化 RecentRuns/Watermarks/MissingDays 三个 slice。
  2. 前端 web/src/lib/api.ts 加 `arr<T>()` 兜底，所有 api.* 返回前把可能为 null 的数组字段过一遍
     （含 daily 的 series 每个 value），页面侧零改动。
- 新增 internal/store/postgres/json_contract_test.go：锁定「空结果集必须编成 []」，
  含 nil slice 编成 null 的对照组，以及直接驱动 collectDaily 空路径的用例（不依赖数据库）。
- **项目约定（后续新增查询必须遵守）**：任何返回 slice 的 store 方法都要用 make 初始化，
  绝不 `var out []T`；JSON 响应里的数组字段不允许出现 null。

## 睡眠分期时间线（hypnogram）——把聚合柱状图升级为逐段时间线（同日追加）

**踩到的坑（都是实测截图发现的，编译期一律看不出来）**：
