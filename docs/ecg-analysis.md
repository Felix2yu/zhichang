# 心电分析页设计

本文记录心电图数据分析页（`/ecg`）的设计口径：为什么重做、开源方案怎么选、算法怎么算、数据怎么流、页面怎么组织、每个指标可信到什么程度。

## 1. 背景与目标

旧布局把「记录」当主内容：一长列测量记录 + 一条孤立的波形。问题有三个：

1. **统计维度低**——只有条数和分类计数，回答不了「这段时间心脏状态怎么样」。
2. **列表冗长**——用户要自己在一屏记录里找规律，这是机器该做的事。
3. **波形展示不合理**——原始波形直接摊开，采样率、点数这类参数对非专业用户没有意义。

重做后的目标：

- 把所选时间段的心电数据**聚合成可读的统计视图**：趋势图、分布图、周期对比、关键指标卡片。
- 指标面向非专业用户可解释：**心电分析印象、心率变异性指数、心脏疾病风险关注度、精神压力指数、疲劳指数**，每个都带含义、算法口径与可信度说明。
- 支持**按时间筛选、点选下钻、联动查看波形**。
- 原始技术参数（采样率、点数）不出现在界面上，只以「约 30 秒 · 39 次心跳」这种健康含义转述。

## 2. 开源方案评估

心电信号处理的主流库几乎都在 Python 生态。逐个看能力、输入输出、适用场景与限制：

| 方案 | 分析能力 | 输入 / 输出 | 适用场景 | 限制 |
|---|---|---|---|---|
| **NeuroKit2** | 最全。封装多检测器（Pan-Tompkins 等）+ HRV 全指标（时域/频域/非线性），`ecg_process()` 一键流水线 | numpy 数组 + 采样率 → DataFrame | 研究、快速实验、批量离线分析 | 依赖 numpy/scipy/sklearn，体积大；为交互式研究设计，不是嵌入式库 |
| **BioSPPy** | 经典 Pan-Tompkins 检测 + R 峰校正，信号滤波链完整 | numpy 数组 → 峰索引数组 | 只要检测、不要 HRV 全指标的轻量需求 | 只做信号处理，指数/分析要自己接；维护放缓 |
| **py-ecg-detectors** | 收集 Hamilton、Pan-Tompkins、Engzee、Christov、SWT 等经典检测器的重实现 | numpy 数组 + 采样率 → 峰索引 | 多检测器对比、算法选型验证 | 纯检测，无任何统计层 |
| **pyHRV** | HRV 分析最系统：时域/频域/非线性/几何全指标 + 详细可视化报告 | WFDB 格式文件 → 报表/图 | 学术 HRV 报告生成 | GPL-3.0；输入绑定 PhysioNet 文件格式；重可视化 |
| **hrv-analysis** | 时域/频域/非线性 HRV，输出可序列化 | RR 间期数组 → 指标字典 | 已有 RR 间期、只要统计的服务端 | 不含检测；依赖 pandas |
| **HeartPy** | 检测 + HRV，对可穿戴噪声容忍度专门调优过 | numpy 数组 → 指标 + 图 | PPG/可穿戴噪声数据 | 主要面向 PPG；单导联临床 ECG 非其主场 |
| **WFDB (Python)** | PhysioNet 官方工具链：标准库读取、标注、部分检测 | record/header/dat 文件组 → 数组/标注 | 处理 MIT-BIH 等标准数据集 | 输入是文件格式不是裸数组；为数据集设计 |
| **Go 生态** | 无成熟心电库，只有零散个人实现 | — | — | 等于全部自研 |

**隐私与实时性**对最终选型的影响比算法能力更大：

- 本项目是自托管单二进制部署。任何 Python 方案都意味着多背一个运行时 + 科学计算栈（百 MB 级），且要么走进程外调用（序列化开销、额外进程要守护），要么嵌 CPython（cgo、交叉编译复杂度陡增）。
- 隐私上本项目全部本地计算，不差在「数据去哪」；差在**攻击面与供应链**：零依赖意味着没有可被投毒的第三方库。
- 实时性上，单次测量约 30 秒 × 512Hz ≈ 15k 点，纯 Go 实现约 3ms/条，任何 IPC 方案的固定开销都比计算本身大。

**结论：纯 Go 自实现。** 需要的算法链路（Pan-Tompkins 检测 → 时域 HRV → Baevsky 压力指数 → 规则打分）都是公开发表的标准方法，实现约 500 行、零依赖，换来单二进制部署、最小供应链和 3ms/条的延迟。上述 Python 库在算法研究阶段的对照价值已兑现（检测器调参、指标口径核对），运行期不依赖它们。

## 3. 算法口径

实现位于 `internal/domain/ecg/`（`hrv.go` / `risk.go`），前端只做展示映射，不重复实现打分。

### 3.1 R 峰检测（Pan-Tompkins，适配 512Hz 单导联）

链路：带通滤波（5–12Hz）→ 五点微分 → 平方 → 150ms 积分窗 → 自适应阈值 + searchback 补检 → RR 间期 outlier 过滤。

两处针对 Apple Watch 实测数据的修正，都是被真实数据逼出来的：

- **searchback 补检**（`fillMissed`）：实测最初 35 条记录里 7 条漏搏——部分记录的 R 波幅度交替变化（相差可达 5 倍），固定阈值把低幅度那批整批漏掉。补检只在「间隙 > 1.6 × 中位 RR」的窗口内、用更低的阈值找局部极大，迭代至稳定。修正后 120/120 条真实记录与 Apple 上游心率偏差 < 15%。
- **峰位精修**（`refinePeaks`）：因果积分窗有约 90ms 的系统性延迟，不影响 RR 间期，但图上标记必须落在真实 R 尖上，故在带通信号 [p-180ms, p+50ms] 内找幅值最大点。

阈值取 `max(0.35 × P98, 3 × 中位数)`：3 × 中位数是抗噪底线，防止纯噪声段检出心跳。

### 3.2 时域 HRV

对过滤后的 RR 间期（秒）计算：**SDNN**（整体变异）、**RMSSD**（相邻差异均方根，短时 HRV 的主指标）、**pNN50**、**CV**、平均/最低/最高心率。

**不做频域分析**（LF/HF）：30 秒单导联不满足频域分析的稳态前提，算了也是假精度。

### 3.3 Baevsky 压力指数

`SI = AMo / (2 · Mo · MxDMn)`，50ms 直方图 bin；要求 ≥ 12 个 RR 且 MxDMn ≥ 50ms，否则不出值。

### 3.4 指数打分（锚点线性插值 → 0-100）

指数不是生理测量值，是把底层指标折算成普通人能读的 0-100。锚点：

| 指数 | 底层量 | 0 分 | 100 分 |
|---|---|---|---|
| 心率变异性 | RMSSD | 10ms | 90ms |
| 精神压力 | Baevsky SI | 40 | 400（经 120→30、250→65 分段） |
| 疲劳 | 复合值 | — | — |

疲劳是复合分：`0.45 × (100 − HRV) + 0.30 × 压力 + 0.25 × 心率负荷`（心率负荷 55bpm→0、100bpm→100）。权重是经验值，页面明说「参考级」。

### 3.5 心脏疾病风险关注度（透明规则）

| 触发项 | 起评/加分 |
|---|---|
| 房颤提示 | 55 分起评 + 35 × 占比 |
| 高心率 | 12 × 占比 |
| 无法判定 / 记录欠佳 | 8 × 占比 |
| HRV 指数偏低 | 按均值分档 +12 / +6 |

**规则全部写在界面上**：触发项原样列在卡片下方，用户看到的是「3 次测量提示房颤」这样的清单，不是一个来路不明的分数。它是筛查关注度，不是患病概率。

### 3.6 信号质量门控

quality=poor 的记录（检出心跳 < 8，或检测心率与 Apple 上游心率偏差 > 15%）**一律不出指数**——坏数据算出来的指数比没有指数更坏。fair/good 按采用率（采用心跳 ÷ 按时长推算的期望心跳）分档。指数统计与波形 R 峰标记用同一套检测器，保证图上看到的就是算进去的。

## 4. 数据流

```
HAE 自动化（iPhone/Apple Watch 导出）
  └─ POST /api/ingest/hae
       └─ normalize → ecg_records（判定/心率/时长）+ ecg_voltages（波形数组）
            │
页面 /ecg ── RangePicker 选区间 ──┐
                                   ▼
                    GET /api/ecg/analysis?from&to
                      └─ ECGRangeFull：LEFT JOIN 波形，升序返回
                           └─ worker pool（≤8）并行逐条 analyzeOneECG
                                └─ 检测 → 质量门控 → 指数 → 汇总/分布/环比
                                   │
         ┌─────────────────────────┼──────────────────────┐
         ▼                         ▼                      ▼
  趋势/分布/对比/指数卡      记录列表              GET /api/ecg/waveform?id
  （同一次响应）              （同一次响应）          └─ 波形 + R 峰索引
                                                       （标记与指数同源）
```

关键点：

- **一次请求拿全部统计**：`/api/ecg/analysis` 单次返回点数组、摘要、分布、环比，页面不做 N+1 请求。
- **波形按需拉**：只有用户点选某条记录时才请求 `/api/ecg/waveform`，且服务端同算一遍 R 峰（`peaks` 字段）给图上标记——前端不自己检测。
- **环比**是上一个**等长**周期（`shiftDate` 平移到 [from-N, from-1]），不是自然月上月。
- 区间上限 300 条（`ecgAnalysisLimit`），超出截断。

## 5. 页面结构

```
┌──────────────────────────────────────────────┐
│ RangePicker（最近 7/30/90/365 天 + 自定义）      │
├──────────────────────────────────────────────┤
│ 心电分析印象卡：众数判定 + 占比 + 最近 12 次判定圆点条 │
├────────────┬────────────┬────────────┬────────┤
│ HRV 指数卡  │ 压力指数卡  │ 疲劳指数卡  │ 风险卡  │  各带「?」释义面板
├────────────┴────────────┴────────────┴────────┤
│ 趋势图（hr/hrv/stress/fatigue 切换，点选下钻）     │
├───────────────────────┬───────────────────────┤
│ 判定分布环图（点图例筛选）  │ 与上一周期对比表        │
├───────────────────────┴───────────────────────┤
│ 记录表：时刻 / 判定 / 心率 / 节律 / 信号质量        │  ← 无采样率、无点数
├──────────────────────────────────────────────┤
│ 底部波形面板：约 30 秒 · 39 次心跳 · 平均 78 次/分  │
│             节律略有波动 + R 峰标记                │
├──────────────────────────────────────────────┤
│ 免责声明                                        │
└──────────────────────────────────────────────┘
```

联动设计：**选中态（selectedId）被趋势点、记录行、波形面板三处共享**——点哪里都是「看这一次的波形」；**分布图图例点击 → 记录列表筛选**（`filterCode`，纯前端状态）。默认选中最近一次有波形的记录。

各指标的展示方式：

| 指标 | 展示 | 理由 |
|---|---|---|
| 印象 | 众数判定 + 12 次圆点条 | 单次判定可能偶发，圆点条让「最近稳不稳定」一眼可见 |
| 四个指数 | 0-100 分数 + 档位 chip + 渐变仪表条 | 渐变方向随 higherIsBetter，HRV 条左红右绿，其余反过来 |
| 趋势 | 折线 + 异常判定点着色 | 看趋势是这类指标唯一正确的用法 |
| 分布 | 环图 + 中心总数 | 类别占比是环图的标准答案 |
| 对比 | 六行表 + 按方向上色的增减 | 心率是中性不上色，避免无意义红绿 |
| 波形 | 用户可理解摘要 + R 峰标记 | 原始参数全部转译 |

## 6. 指标口径与可信度

每个指数卡内的「?」面板给四段：含义、怎么算、可信度、怎么看。汇总口径：

| 指标 | 算法 | 可信度定位 | 边界 |
|---|---|---|---|
| 心率变异性指数 | RMSSD 锚点折算 | 中等：标准时域算法，但 30 秒样本波动大 | 看趋势，不抠单次绝对值 |
| 精神压力指数 | Baevsky SI 折算 | 中等偏低：学术常用方法，但 30 秒直方图粗、个体差异大 | 只看相对变化，不跨人比较 |
| 疲劳指数 | 经验复合值 | 参考级：无临床金标准，权重是经验值 | 连续走高才值得行动 |
| 风险关注度 | 透明规则 + 触发项清单 | 参考级：30 秒间歇测量可能整段漏掉间歇房颤 | 关注度高→就医；低≠排除 |

全局免责声明：异常提示以医疗机构意见为准。

## 7. 已知限制

- **单导联、30 秒**：数据源就是 iPhone/Apple Watch 的单导联短时测量，间歇性房颤可能漏检；这不是算法能补的，只能靠频繁测量摊低漏检概率。
- **指数是折算值不是生理量**：0-100 是展示刻度，不对应任何临床分级。
- **趋势优先**：所有指数的正确用法是与自己的历史比，不是与别人比、不是抠单次。
- **无波形记录**：HAE 只同步了判定没同步波形的记录，或有波形但一个心跳都检不出（过短、平直），出不了指数；在表里显示「无波形」，不进任何统计。
- **对比窗口等长平移**：上一周期是机械平移，不保证有对称的测量密度；对比表脚注已说明。
